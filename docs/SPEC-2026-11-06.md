# Spec — review follow-up for cmd-compress 0.5.2

Source: `docs/REVIEW-2026-11-06.md` (F1-F7). Baseline `e4fe7dc`.

## Requirements

| ID | Requirement | Acceptance check |
|---|---|---|
| R1 | `mods/rtk.ts` is below 800 lines; condensing and command-line/rewrite logic live in their own modules; no behaviour change. | `wc -l mods/rtk.ts` < 800; all 246 tests pass unchanged in intent; only import lines change in tests. |
| R2 | A failing temp-dir cleanup cannot escape `afterToolCall`. | A unit test forces `rmSync` to throw and asserts the hook still returns a result. |
| R3 | The sub-agent block is appended once per call and is not suppressed by a bare tag mention. | Unit test: prompt containing `<rtk>` as prose still gets the block; a prompt already carrying the block does not get a second. |
| R4 | `beforeToolCall` shell path and `afterToolCall` spawn gates wait for the version probe, matching the agent branch and `appendSystemPrompt`. | Typecheck + behaviour test with a pending probe: no `rtk rewrite` spawn before the probe settles. |
| R5 | `pipeCommand` never returns the known-broken double-quoted cmd.exe line. | With `shell.wrap` and no `scriptPath`, `pipeCommand` throws; existing Windows test still passes. |
| R6 | `types/harness.d.ts` contains no section-divider comments. | `grep -c '/\* ---' types/harness.d.ts` = 0; typecheck clean. |
| R7 | Windows `verify-mods` skips the inspect report explicitly instead of invoking `cmd.exe` and swallowing the failure. | Code path is `process.platform === 'win32'` gated and prints the reason; Linux/macOS verify still shows the report. |

## Non-goals

- No change to compression heuristics, byte floors, fidelity rules, or prompt text.
- No new dependency, no new flag, no behaviour change for F8-F10.
- No version bump; the release decision belongs to the maintainer.

## Fail conditions

Any test regression, any new export missing from a module header, any file over 800 lines except test files, or a `cmd mods inspect` failure.
